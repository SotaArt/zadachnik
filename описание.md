# 📋 Задачник — Техническое описание проекта

**Версия:** 35
**Дата актуализации:** октябрь 2026
**Онлайн:** https://sotaart.github.io/zadachnik/
**Синхронизация:** GitHub Gist (приватный gist, токен хранится в браузере)
**Тип приложения:** Одностраничное веб-приложение (SPA), автономный HTML-файл
**Назначение:** Управление личными задачами, учёт рабочего времени, ведение сессий контроля менеджеров (КМ) с фиксацией звонков и ОС, формирование ежедневной отчётности.

---

## 1. Общее описание

**Задачник** — это полностью автономное офлайн-приложение для персонального планирования, хронометража рабочего времени и супервизии менеджеров по продажам (контроль менеджеров, КМ).

Приложение реализовано как **единый HTML-файл** (`tasker.html`), не требующий:
- установки;
- интернет-соединения;
- серверной части;
- регистрации и авторизации;
- сторонних библиотек и фреймворков.

Всё работает на чистом стеке **HTML + CSS + Vanilla JavaScript (ES2017+)** и хранится локально в браузере через `localStorage`, с дополнительной возможностью синхронизации в файл через File System Access API (Chrome / Edge) и резервного копирования через JSON-экспорт.

**Целевая аудитория:** руководитель отдела продаж / супервайзер, ведущий одновременно личные задачи, контроль рабочего времени и работу с менеджерами (КМ) по звонкам.

## 2. Архитектура

### 2.1 Структура
Приложение построено по принципу **монолитного одностраничного SPA**:

```
tasker.html
├── <style>  — весь CSS (~1500 строк)
├── <body>   — разметка приложения
│   ├── Шапка (header)
│   ├── Баннер бэкапа
│   ├── Вкладки (tabs)
│   ├── Панель «📋 Задачи»
│   ├── Панель «⏱ Моё время»
│   ├── Панель «👥 Сотрудники»
│   └── Вспомогательные элементы (баннер напоминаний, статус автосохранения)
└── <script> — весь JS (~2500 строк)
    ├── Конфигурация и ключи хранилища
    ├── Загрузка/сохранение данных
    ├── Утилиты форматирования
    ├── Логика вкладок
    ├── Модуль «Задачи»
    ├── Модуль «Моё время»
    ├── Модуль «Срез дня»
    ├── Модуль «Сотрудники / Сессии»
    ├── Модуль «Отсутствия КМ»
    ├── Модуль «История сессий»
    ├── Модуль «Итог дня»
    ├── Экспорт / импорт
    ├── Будильник
    └── Инициализация
```

### 2.2 Паттерны

| Паттерн | Применение |
|---|---|
| **Модульная изоляция** | Каждая функция отвечает за одну область (renderWork, renderTeam, renderPulse) |
| **Единая точка сохранения** | Функция `save()` вызывает `saveLocal()` + `saveToFile()` |
| **Единая точка рендера** | При любом изменении вызывается перерисовка нужного блока |
| **Event delegation** | Обработчики навешиваются на элементы после рендера |
| **Debounce** | Для автосохранения в файл (800 мс) |
| **LocalStorage as DB** | Прямое чтение/запись JSON-структур |

### 2.3 Хранилище

Все данные хранятся под **фиксированными ключами** в `localStorage`, не зависящими от версии кода:

```javascript
tasker_data_v1_tasks      — массив задач
tasker_data_v1_work       — мой лог времени
tasker_data_v1_emp        — справочник КМ
tasker_data_v1_empwork    — лог времени КМ
tasker_data_v1_empabsences — отметки отсутствия КМ (опоздание/обед/иное)
tasker_data_v1_sessions   — сессии с КМ
tasker_data_v1_pulse      — срез дня (план/факт)
tasker_data_v1_timer      — активный мой таймер
tasker_data_v1_emptimer   — активная сессия/таймер КМ
tasker_data_v1_meta       — служебные метаданные (последний экспорт)
```

Такая схема гарантирует **сохранность данных при обновлении кода** — версия приложения меняется, а ключи остаются.

## 3. Функциональные модули

### 3.1 Модуль «📋 Задачи»

**Назначение:** личный таск-менеджер с дедлайнами и напоминаниями.

**Возможности:**
- Создание задачи с текстом, сроком исполнения и напоминанием
- Повторяющиеся задачи: ежедневно / по будням / еженедельно / ежемесячно
- Автоматическое создание следующей задачи при закрытии повторяющейся
- Отметка «выполнено» с фиксацией точной даты и времени
- Определение статуса «в срок» / «с опозданием»
- Фильтры: активные / на сегодня / просроченные / выполненные / все
- Поиск по тексту
- Группировка: просрочено / сегодня / завтра / на неделе / позже / без срока / выполненные
- Inline-редактирование текста задачи
- Статистика: сделано за сегодня / за 7 дней / всего / просрочено / % в срок

**Модель данных:**
```javascript
{
  id: Number,
  text: String,
  deadline: Number|null,     // timestamp
  remind: Number|null,       // timestamp
  repeat: String|null,       // daily|weekdays|weekly|monthly
  done: Boolean,
  doneAt: Number|null,
  notified: Boolean,         // флаг отправки уведомления
  created: Number
}
```

### 3.2 Модуль «⏱ Моё время»

**Назначение:** хронометраж личного рабочего времени.

**Возможности:**
- **Таймер в реальном времени** — старт/стоп с точностью до секунды, переживает перезагрузку страницы
- **Ручной ввод** — дата, начало, конец
- **Прогресс от рабочей нормы (8 ч)** — процент, остаток / переработка
- **Расчёт «неучтённого времени»** в рабочем окне 9:00–18:00:
  - Поиск пробелов между записями
  - Объединение пересекающихся интервалов
  - Отображение в сводке со скроллом
  - **Клик по интервалу → модалка быстрого добавления действия** в этот промежуток
- Группировка по дням с прогрессом (Сегодня / Вчера / даты)
- Фильтры периода в верхней карточке-сводке: Сегодня / 7 дней / Месяц / Всего + кнопка «Отчёт по мне»
- Отчёт по выбранному периоду с копированием/скачиванием

**Модель данных:**
```javascript
{
  id: Number,
  text: String,
  date: 'YYYY-MM-DD',
  start: 'HH:MM',
  end: 'HH:MM' | null,       // null = активная запись
  startTs: Number,
  endTs: Number|null,
  syncEmployeeId: Number|null,   // если запись синхронна с сессией КМ
  syncEmployeeName: String|null,
  created: Number
}
```

**Специальные возможности:**
- Записи с флагом `syncEmployeeId` помечаются бейджем «🤝 Синхрон с [КМ]»
- Живые записи (`endTs === null`) отображаются как `— идёт` с индикатором `(live)`

### 3.3 Модуль «📊 Срез дня»

**Назначение:** ежедневный срез ключевых показателей в формате план / факт.

**Возможности:**
- Настраиваемые поля (добавление / редактирование / удаление)
- Каждое поле: название, план, факт
- Хранение **по датам** — на каждый день отдельный набор полей
- **Автоподстановка полей** — если на сегодня среза ещё нет, названия полей автоматически берутся из вчера и позавчера (объединяются, без дублей), план/факт остаются пустыми — достаточно откорректировать значения
- Кнопка **«📋 Копировать»** — формирует текст в формате `Название план/факт` и кладёт в буфер обмена (для быстрой вставки в мессенджер)
- Автосохранение в реальном времени при вводе

**Модель данных:**
```javascript
dailyPulse = {
  '2026-10-13': [
    { label: 'Прогноз/Открыто', plan: '4', fact: '0' },
    { label: 'Платные пу', plan: '3', fact: '0' },
    // ...
  ]
}
```

### 3.4 Модуль «👥 Сотрудники / Сессии с КМ»

**Назначение:** контроль работы менеджеров через сессии с фиксацией звонков.

**Ключевая концепция:** сессия с КМ — это **отдельный процесс**, который:
1. Запускается кнопкой ▶ Старт
2. Ведёт параллельный хронометраж в моём логе (с пометкой «🤝 Работа с [КМ]»)
3. Фиксирует звонки КМ в реальном времени
4. Сохраняется в историю

**Возможности:**
- Справочник КМ (добавление / удаление через верхнюю панель)
- Тема сессии (обязательное поле)
- **Таймер сессии** — реальное время, переживает перезагрузку
- **Таймер текущего звонка** — отдельно от сессии
- Метки звонка: ✅ «есть диалог» / ❌ «отказ или иная причина»
- Поле ОС по звонку (свободный текст)
- **Развивающая ОС для КМ** — кнопка 📋 у поля ОС звонка и «📋 Развивающая ОС» в заметках сессии: список из 50 типовых развивающих комментариев (открытое выявление потребности, small talk, цель звонка = встреча, слова-паразиты, обработка возражений, ценность vs цена и т.д.), добавляются по клику; повторно один и тот же комментарий в один текст не добавляется (отмечается зачёркиванием)
- **Скрипты звонка** — во вкладке «📞 Скрипты звонка» того же окна: 16 готовых скриптов по группам (продажа очной встречи, РКО, эквайринг, карта «Альфа Онли») для саморазвития КМ; встречи только очные, открытие РКО онлайн — только при наличии оффера на онлайн-открытие; добавляются по клику в тот же текст, без дублей
- **Блочная подсветка ОС/скриптов** — добавленные комментарии и скрипты оформляются отдельными блоками с цветной подписью: `💬 ОС` (фиолетовый) и `📞 Рекомендую скрипт` (голубой); превью перед вставкой, дубли не добавляются
- **Отметка отсутствий КМ** — кнопка «🕓 Отметить отсутствие» (в панели «Сотрудники»): фиксируется, когда КМ не работал — ⏰ опоздание, 🍽 обед, 🚶 ранний уход, ☕ отлучка/перерыв, 📌 иное отсутствие. Для каждого: КМ, дата, начало/конец (с авто-подстановкой типовых интервалов), комментарий. Отсутствия:
  - учитываются в сводке дня и в отчёте по команде (по КМ);
  - редактируются и удаляются;
  - попадают в фильтр по периоду (сегодня / 7 дней / месяц / все);
  - сохраняются, экспортируются и импортируются вместе с остальными данными
- **Контроль лимитов и замечания** — автоматически по каждой отметке отсутствия формируются текстовые замечания (не цветом, а словами) в отчётах и на карточках:
  - **Опоздание** (тип `late`) — всегда замечание + запрос **объяснительной записки на имя НО** со сроком до следующего дня после выявления;
  - **Обед** (тип `lunch`) — замечание при превышении лимита **45 минут** (`LUNCH_LIMIT_MIN = 45`), без запроса;
  - **Иное/отлучка** (`other`/`break`) без указанной причины — замечание + запрос **пояснения** на имя НО.
  - Логика в функциях `getAbsenceIssues()` / `collectAbsenceRemarks()`; отдельного поля «замечание» в базе нет — оно выводится динамически из типа, длительности и наличия причины
- **Рекомендованные скрипты из ОС** — блоки `📞 Рекомендую скрипт` внутри ОС звонков и заметок сессий извлекаются (функция `extractScripts`) и выводятся сводно в отчётах
- Список завершённых звонков построчно: `#N  HH:MM–HH:MM  длительность  метка  ОС`
- Заметки по сессии (общий ОС)
- Сводка в реальном времени: количество звонков, ✅, ❌, общее время в звонках
- Автоматическое завершение открытого звонка при закрытии сессии

**Правила изоляции:**
- Одновременно может идти **только один** процесс:
  - мой таймер
  - сессия с КМ
  - (синхронный процесс — это одна сущность)
- Попытка запустить второй процесс → alert + блокировка кнопок

**Модель данных сессии (активная и в истории):**
```javascript
{
  id: Number,
  employeeId: Number,
  topic: String,
  startTs: Number,
  endTs: Number,
  calls: [
    {
      startTs: Number,
      endTs: Number,
      mark: 'ok'|'fail'|null,
      os: String
    }
  ],
  notes: String
}
```

**Модель данных отметки отсутствия:**
```javascript
{
  id: Number,
  employeeId: Number,
  date: 'YYYY-MM-DD',
  type: 'late'|'lunch'|'leave'|'break'|'other',
  start: 'HH:MM',
  end: 'HH:MM',
  startTs: Number,
  endTs: Number,
  note: String,
  created: Number
}
```

### 3.5 Модуль «📂 История сессий»

**Назначение:** просмотр и анализ проведённых сессий.

**Возможности:**
- Фильтр по периоду: Сегодня / 7 дней / Месяц / Всего (единый для времени КМ, отсутствий и истории сессий) — кнопки в верхней карточке-сводке вместе с выбором КМ
- Верхняя карточка: выбор КМ + монитор (Всего с КМ, записей, отсутствий, число КМ) + периоды
- Карточка сессии объединяет таймер/старт и поле темы сессии
- Две кнопки действий в одну строку: «🕓 Отметить отсутствие» и «📤 Отчёт по команде»
- Три сворачиваемых раздела (по умолчанию свёрнуты): записи времени КМ, «Отсутствия КМ», «История сессий»
- Аккордеон-список всех сессий (сортировка от новых к старым)
- В свёрнутом виде: КМ, тема, дата, длительность, звонки, ✅, ❌
- В развёрнутом виде:
  - Сводная статистика: всего звонков, конверсия, время в звонках, средний звонок
  - Список всех звонков с метками и ОС
  - Заметки по сессии
  - Кнопки «📄 Отчёт» и «🗑 Удалить»
- Экспорт отчёта по сессии: `.txt` (для письма), `.csv` (для Excel), копирование

### 3.6 Модуль «📊 Итог дня»

**Назначение:** сводная отчётность за выбранную дату.

**Возможности:**
- Выбор даты (по умолчанию — сегодня)
- Формирование единого текстового отчёта
- Экспорт в `.txt` и `.csv`
- Копирование в буфер

**Структура отчёта:**

1. **📌 Срез дня** — все поля с планом и фактом + итог
2. **✅ Задачи** — три раздела:
   - Выполнено в этот день (с временем и статусом «в срок/с опозданием»)
   - Поставлено в этот день (со статусом)
   - В работе сейчас (с дедлайнами, сортировка по срочности)
   - Статистика по задачам
3. **⏱ Моё время** — записи за день + процент от нормы + разбивка «в сессиях / самостоятельно» + список неучтённых интервалов
4. **👥 По сотрудникам** — по каждому КМ:
   - Общее время, количество сессий
   - Сводка по звонкам с конверсией
   - Детализация по каждой сессии: тема, все звонки с метками и ОС (блоками `💬 ОС` / `📞 Рекомендую скрипт`)
   - Общие заметки по сессии
   - Рекомендованные скрипты (сводно)
   - Отсутствия КМ за день
   - ⚠️ Замечания (опоздание, превышение обеда > 45 мин, отсутствие без причины)
   - ✉️ Запросы объяснительных/пояснений на имя НО со сроком до следующего дня
5. **📌 Общая сводка** — итоговые показатели дня (включая отсутствия КМ и число замечаний)

**Отчёты (текстовые, `.txt`):**
- **«📊 Итог дня»** — полный отчёт по дате: срез, задачи, моё время, все КМ со всеми ОС, скриптами, отсутствиями, замечаниями и запросами
- **«📤 Отчёт по команде»** — разбивка по каждому КМ за выбранный период (сегодня / 7 дней / месяц / все) со всей ОС, скриптами, замечаниями и запросами объяснительных
- **«📋 Отчёт о моей работе»** — только мои записи времени за период: по дням, синхроны с КМ, неучтённые интервалы, итоги «в сессиях / самостоятельно»

### 3.7 Модуль «🛰 КМ-листы» (кабинет КМ + облако GitHub Gist)

**Назначение:** персональный кабинет каждого КМ (таймер задачи, чеклист дня, учёт времени, напоминания, антифрод) и единый облачный список КМ для руководителя.

**Единый список КМ (важно):** добавление и удаление КМ — **только** во вкладке «🛰 КМ-листы». Когда облако подключено, кнопки «+» / «🗑» в шапке скрываются, вкладка «👥 Сотрудники» получает подсказку, а её список автоматически синхронизируется с облаком (в каждое локальное имя пишется `cloudId` = id в gist). Сессии, отсутствия и отчёты продолжают работать, но источник истины — один: облако.

**Роли и доступ:**
- **Руководитель (админ)** — вкладка «🛰 КМ-листы»: подключение облака (GitHub-токен scope `gist`), добавление/удаление КМ, **ПИН виден на карточке**, генерация персональной ссылки, живой дашборд (онлайн/офлайн, таймер, время за сегодня, чеклист), назначение задач в чеклист, напоминания, просмотр полного листа КМ.
- **КМ** — открывает свою персональную ссылку вида `…#km?g=<gist_id>&t=<token>&id=<km_id>`, выбирает себя из списка и вводит ПИН-код. Видит и редактирует **только свой** лист.

**Кабинет КМ:**
- **⏱ Задача дня** — кнопка «▶ Старт задачи» активируется только после ввода темы (иначе подсвечивается поле темы). Поле темы блокируется на время задачи
- **Комментарий по задаче** — обязателен при ручной остановке, если во время задачи не было ни одного звонка (иначе надо заполнить)
- **📞 Звонки** — доступны только во время активной задачи: «▶ Набор» / «⏹ Отбой», статус ✅/❌, комментарий по звонку и общий комментарий. Каждый звонок фиксируется (начало, конец, длительность, статус, комментарий). Завершённые звонки можно править (статус, заметка) и удалять
- **Статистика дня** — рабочее окно (09:00–18:00), норма (8 ч), отработано, не использовано, число звонков
- **✅ Чеклист дня** — свои пункты (КМ добавляет сам, удаление с подтверждением) и назначенные руководителем (📌, КМ может только отметить, но не удалить). Отдельного блока «Мои задачи» больше нет — всё в чеклисте
- **⏱ Моё время сегодня** — записи за день (с комментарием)
- **⏰ Напоминания на сегодня** — что и когда приходит от руководителя, плюс отметка «✓ выполнено»
- **🛡 Активность / антифрод** — журнал событий
- **Сворачиваемые модули** — клик по заголовку карточки сворачивает/разворачивает её

**Админ-панель (вкладка «🛰 КМ-листы»):**
1. **➕ Добавить КМ** — имя + ПИН (4–6 цифр); ПИН выводится на карточке КМ
2. **✅ Задача в чеклист дня** — текст + выбор целей: «Всем КМ», несколько отмеченных или один конкретный. Ниже — список назначенных задач с кнопками ✏️ (изменить текст) и ✕ (удалить)
3. **⏰ Напоминания (будильники)** — время (HH:MM) + текст + кому; список с кнопками ✏️ (изменить время/текст) и ✕ (удалить)
4. **Карточки КМ** — ПИН, онлайн/офлайн, таймер, время за сегодня, «🔗 Ссылка», «👁 Лист», «🗑»
5. Все карточки админ-панели **сворачиваются** кликом по заголовку

**Единый источник задач:** назначенные руководителем задачи хранятся отдельно в `_tasks.json` (`{ id, text, kmIds, created }`) — это авторитетный список. КМ на каждом цикле подтягивает его и **пересобирает** админские пункты чеклиста из него (сохраняя только отметки `done`), поэтому изменить или удалить назначенную задачу можно централизованно, а собственные пункты КМ не затрагиваются.

**Напоминания / будильники:** хранятся в файле `_reminders.json`. КМ читает только свои (`kmIds: 'all'` или список его id) при каждом heartbeat и проверяет расписание каждые 30 с. При наступлении (окно 15 минут) — системное уведомление `Notification` + звук + всплывающее окно, отметка в `doc.fired`, запись `alarm` в журнале событий.

**Антифрод (триггер «фон + бездействие»):**
- при сворачивании/уходе со вкладки (`visibilitychange`) таймер автоматически останавливается — событие `bg`
- при бездействии > 10 минут (нет мыши/клавиатуры/касаний/скролла) — событие `idle`
- при закрытии приложения (`pagehide`) — событие `offline`
- факт остановки фиксируется в журнале событий и виден руководителю
- «живость» КМ — heartbeat каждые 30 секунд (`lastSeen`); онлайн = активность < 90 секунд

**Хранение:** отдельный приватный gist с описанием «Задачник КМ»; **один файл на КМ** — `km_<id>.json` вида `{ id, name, pin, pinHash, doc }` (ПИН хранится открыто для руководителя + хэш `SHA-256('km:'+id+':'+pin)` для входа), плюс общие `_reminders.json` и `_tasks.json`. `doc` содержит `{ checklist, entries, events, fired, calls, call, timer, lastSeen, day }`, где `calls` — завершённые звонки КМ, `call` — активный звонок. Обмен — через GitHub Gist REST API; PATCH обновляет только файл этого КМ, поэтому одновременная запись разных КМ не конфликтует. При push КМ читает `_tasks.json`, **пересобирает админские пункты чеклиста** (админские — из облака, свои — из локальных, отметки `done` сохраняются) и записывает обратно. При подключении облака (модалка «⚙ Настройки облака») приложение находит или создаёт приватный gist; настройки (токен, `gist_id`, логин) хранятся в `localStorage` (`tasker_km_cfg`) и приходят КМ из персональной ссылки.

**Безопасность:** доступ к облаку даёт GitHub-токен, вшитый в персональную ссылку КМ; поэтому ссылки нельзя публиковать, а лучше выдавать личные токены. Секретных данных на сервере нет — только листы КМ.

## 4. Технические особенности

### 4.1 Сохранение данных

Три уровня защиты:

1. **Автоматическое сохранение в localStorage** — происходит при каждом действии (через `save()`)
2. **Автосохранение в файл** (Chrome/Edge) — через File System Access API, запись раз в 0,8 секунды после последнего изменения
3. **Ручной экспорт** — JSON-файл со всеми данными (задачи + время + КМ + сессии + срез)

Дополнительно:
- **Индикатор состояния** в правом нижнем углу
- **Баннер напоминания** о бэкапе при отсутствии экспорта более 1 дня
- **Предупреждение при закрытии** вкладки, если давно не делался бэкап

### 4.2 Устойчивость таймеров

Таймеры не сбрасываются при перезагрузке страницы. Механизм:
1. В `localStorage` хранится `startTs` активного процесса
2. При загрузке приложения проверяется наличие активного таймера
3. Идёт восстановление визуального состояния и продолжение отсчёта от исходного `startTs`
4. Восстанавливаются: активный звонок, заметки, состояние UI

### 4.3 Проверки целостности

Во всех критических функциях рендера присутствуют **проверки на null**:
```javascript
const el = document.getElementById('...');
if (!el) return;
```
Это защищает от полного падения скрипта при отсутствии элемента в DOM.

### 4.4 Работа с часовыми поясами

- Все даты хранятся как **timestamps (ms)** — это UTC-независимо
- Для отображения используется локальный формат
- Для ввода даты/времени — `<input type="date">` и `<input type="time">`

### 4.5 Совместимость

- **Chrome / Edge / Firefox / Safari** — полная поддержка
- **Мобильные браузеры** — работает, адаптивная вёрстка под узкие экраны
- **File System Access API** — только Chrome и Edge (для автосохранения в файл; не критично)
- **Уведомления браузера** — где поддерживается (для напоминаний)

## 6. Безопасность и приватность

- **Данные не покидают устройство** — вся информация хранится локально
- **Нет внешних запросов** — приложение не обращается ни к каким серверам
- **Нет аналитики** — не подключаются сторонние счётчики
- **Отсутствие зависимостей** — нет npm-пакетов, CDN, шрифтов

**Рекомендация по использованию:** регулярно (раз в день / неделю) делать экспорт JSON в отдельную папку — это единственный надёжный способ гарантировать сохранность данных.

## 8. Ограничения

| Ограничение | Описание |
|---|---|
| **Локальность данных** | Данные привязаны к конкретному браузеру и адресу (origin). Переход на другой браузер / устройство — данные не переносятся автоматически |
| **Очистка localStorage** | Браузер может почистить localStorage при переполнении или по решению пользователя |
| **Автосохранение в файл** | Требует повторного выбора файла после перезапуска браузера (ограничение безопасности File System Access API) |
| **Служба напоминаний** | Работает, пока открыта вкладка приложения. Браузер не может будить ноутбук сам |
| **Единый процесс** | Одновременно может идти только один таймер (моя работа или сессия с КМ) |

## 9. Итоги

**Задачник** — это самодостаточное приложение для комплексного управления личной эффективностью и работой с командой. Приложение сочетает в себе:

- планировщик задач с напоминаниями,
- хронометраж рабочего времени с контролем неучтённых интервалов,
- управление сессиями с менеджерами и фиксацией каждого звонка,
- ежедневную отчётность в едином формате.

**Ключевые преимущества:**
- Полная автономность и приватность
- Минималистичный стек без зависимостей
- Устойчивость к перезагрузкам и обновлениям кода
- Три уровня сохранения данных
- Готовность к развёртыванию на GitHub Pages без изменений

Приложение спроектировано так, чтобы **один человек мог вести весь цикл работы**: от личного планирования до разбора звонков менеджеров и отправки итогового отчёта в конце дня.
